## 1. 离线训练闭环

```text
行为/曝光日志
  → LogToFeature / USD 序列补全
  → OneRec SequenceExample
  → 样本筛选与奖励特征
  → RQ-VAE 语义 ID
  → HSTU/序列生成模型
  → checkpoint + 模型元信息
  → Encoder / Decoder 发布
```

RQ-VAE 与序列模型是两个版本耦合点：序列训练数据中的 token 编码必须对应同一套 codebook、层数和 SID 打包规则。模型发布不能只更新 checkpoint，还要同步：

- `model_version` 与 `data_name`；
- token/codebook 版本；
- trie 或 KV creative 版本；
- 每级 token 位宽与树深；
- Encoder/Decoder 支持的最大 beam。

## 2. 在线触发

Mixer 构造召回请求后，主 Retrieval Proxy 与 GprHub 侧路成为同级任务。正式和灰度环境通常保留两路并发，主召回不会因为 GprHub 实验命中而停止。

GprHub 侧路内部再根据位置级生成式开关选择：

- 生成式实现：`GenerativeRecall` 进入六节点生成式 DAG；
- 对照实现：侧路调用兼容旧 GPR 的 Retrieval Proxy 流程。

只有隔离仿真模式在满足专用条件时跳过主召回。多广告位请求在 GprHub service 层拆分，每个 position 复制自己的 `pos_id`、实验参数、cache node 和监控 tag。

## 3. 新生成式召回 DAG

![OneRec 从入口到召回缓存的生产链路](assets/diagrams/onerec/zh/retrieval-pipeline.svg)

六个生成式节点的职责：

| 节点                | 输入                   | 输出                               | 失败时表现                   |
| ------------------- | ---------------------- | ---------------------------------- | ---------------------------- |
| Entry               | 单广告位请求、实验参数 | `GenerativeData`、quota、beam 参数 | 参数缺失或路径未命中         |
| Datahub             | 用户与上下文标识       | 生成式行为序列、模型输入上下文     | 空序列、RPC 超时             |
| Encoder             | 结构化序列             | 共享 user embedding、模型版本      | 输入 schema/模型版本错误     |
| Decoder             | embedding、树/模型参数 | SID 序列与分数                     | 空 SID、beam 越界            |
| KV Creative         | SID                    | TID 列表                           | 版本错、SID miss、分片空响应 |
| Creative List Build | TID 与分数             | 按 AID 去重的创意列表              | TID→AID 缺失、全被去重       |

之后进入 GprHub 的公共 quota、属性过滤、创意服务和粗排子图。生成式 DAG 与侧路旧 GPR 对照大体同构，但当前静态图仍存在少量节点差异，实验归因时需要显式核对。

## 4. Ranking 与主链路合并

主链路继续执行常规召回、粗排和主 Ranking。OneRec 在 GprHub 中完成公共过滤与召回侧 Scoring，再把结果写入 Retrieval Cache。Ranking 侧通过 Fetch 接口等待 `fill_done`，随后完成候选绑定、轻量 DocWash、独立 prediction/pCTR 和出价上下文构建。

![OneRec 主链路与侧路的合并位置](assets/diagrams/onerec/zh/merge-paths.svg)

这个拓扑的价值是隔离：

- OneRec 在合并前不占用主路 DocWash 和主预测候选集合；
- 失败时可放弃侧路结果而不阻塞主链路；
- 最终按 AID 与创意两级合并去重，再进入统一重排、约束和拍卖。

完整执行语义见 [[推荐系统理论/OneRec/召回粗排精排重排源码链路|召回、粗排、精排与重排源码链路]]。

## 5. 缓存同步语义

Mixer 的召回 RPC 与 Ranking Fetch 是异步配合：

1. GprHub 为请求/广告位创建 cache node；
2. 生成式流水线结束后写广告列表、`recall_path`、实验标签并置 `fill_done`；
3. Ranking Fetch 命中 node 时，若尚未完成则等待到超时；
4. 成功后返回广告与上下文，失败区分 key miss、timeout、empty result。

必须分开监控“流水线本身慢”和“Fetch 等待慢”。前者看 GprHub 分段 RPC/Op；后者看 `fetch_wait_latency` 和 cache key 命中。

## 6. 关键不变量

- 主路与 GprHub 侧路在正式流量中可以并发；GprHub 内部同一 position 只选择生成式或旧 GPR 对照实现；
- Encoder、Decoder、RQ-VAE codebook 与 KV creative 版本一致；
- SID 打包/解包层数和每层位宽一致；
- Decoder 输出分数随 SID 保持同序；
- Z-order/分片汇合后再按 quota 截断，避免单分片垄断；
- TID→AID 后按 AID 去重，不把同广告多创意误算成多广告；
- cache 写入量与 Ranking Fetch 返回量可交叉核对；
- AID overlap、creative overlap 与最终全局创意去重可独立核对；
- OneRec 失败不应扩大为主链路失败。
