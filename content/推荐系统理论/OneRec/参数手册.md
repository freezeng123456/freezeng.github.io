参数必须按调用链分组。相同名字出现在样本、训练和在线服务中，不代表同一层含义。

## 在线生成式召回

| 参数                             | 有效来源/回退                   | 硬约束                     | 主要影响                          |
| -------------------------------- | ------------------------------- | -------------------------- | --------------------------------- |
| `gpr_pam_beam_width`             | 位置实验；缺失时 Entry 回退 180 | 当前 Decoder 上限 180      | Decoder 前缀搜索宽度、SID 数、P99 |
| 共享结构初值                     | 源码中存在 200，但 Entry 会覆盖 | 不能当作线上有效值         | 仅用于识别默认值覆盖风险          |
| `gpr_beam_search_topk`           | 位置实验；大于 0 时生效         | 不超过可输出 SID           | 最终 SID 截断                     |
| `gpr_pam_beam_width_shard_ratio` | 位置实验；缺失时保持安全缺省    | 分片合计需覆盖请求预算     | 分片负载与召回分布                |
| trie level / version             | trie/model 元数据               | 与模型、SID 打包和 KV 一致 | token 层数与 KV 命中              |
| unique filter                    | quota/策略计划                  | SID 格式一致               | 去除重复 SID                      |
| KV/output quota                  | 策略给出；缺失兜底 1000         | 非负且有上限               | SID 扩展后的 TID 截断             |

详细 beam 语义见 [[推荐系统理论/OneRec/Beam-Search\|Beam Search]]。

## 在线 RPC 与超时

| 参数                       | 来源与优先级                                                | 说明                                                   |
| -------------------------- | ----------------------------------------------------------- | ------------------------------------------------------ |
| Datahub timeout            | 位置/服务配置                                               | 获取序列与生成式上下文；单独统计 RPC 与业务空结果      |
| Encoder/Decoder/KV timeout | 分段服务配置                                                | 每段独立预算，不能只保留一个总 infer timeout           |
| Ranking Fetch timeout      | 位置级 `gpr_server_hub_timeout_ms` 优先，服务 fallback 兜底 | 等待 Retrieval Cache `fill_done`，到期后侧路 fail-open |
| cache 正常/硬过期          | cache 服务配置                                              | 分别清理已完成但未消费的节点和生产者失联节点           |

旧评审记录中的固定超时只代表当时的联调快照，不能继续标成线上现值。Fetch timeout 需要同时满足两项约束：覆盖可接受的侧路 cache-ready 分位数，并留在主 Ranking 总 deadline 内。调大超时只能提升部分侧路覆盖，还可能把等待直接转化为最终 P99。

## Ranking、合并与重排

| 参数                          | 有效规则                       | 主要影响                           |
| ----------------------------- | ------------------------------ | ---------------------------------- |
| `ranking_enable_fetch_gpr`    | 服务能力与位置实验共同命中     | 侧路是否进入 Ranking               |
| `gpr_bind_adtable_batch_size` | 代码 fallback 10               | 广告表绑定批次、吞吐与尾延迟       |
| GPR prediction / pCTR gates   | 按位置实验与 Ranking 能力控制  | 侧路精排分数与成本                 |
| OneRec relevance gate         | 全局开关 + 位置实验 + 指定场景 | 是否向公共重排注入生成式相关性因子 |
| relevance threshold           | 通过阈值后截断到 $[0,1]$       | 因子覆盖率与重排强度               |

这组参数需要与 main-only、side-only、AID overlap 和 creative overlap 一起上报。只统计最终广告数，会掩盖 Fetch 未触发、绑定丢字段、DocWash 删量和合并去重带来的差异。

## 样本与策略优化

| 参数                |   示例值 | 作用               | 调优风险                        |
| ------------------- | -------: | ------------------ | ------------------------------- |
| `return_ad_count`   |       40 | 生成器返回广告上限 | 过小截断，过大增加样本/排序成本 |
| `grpo_m_items_kept` |       20 | 组内保留候选数     | 必须不大于有效候选              |
| `creative_top_k`    |     1024 | 上游候选池         | 过大带入长尾噪声                |
| `creative_sample_n` |       20 | 创意采样数         | 影响多样性与方差                |
| `sampling_percent`  |      100 | 总样本采样率       | 改变数据量和分布                |
| `llm_sampling_rate` |     0.05 | 昂贵语义奖励覆盖率 | 成本/方差权衡                   |
| `gen_type`          | `MID_TD` | 输出格式           | trainer 必须同 schema           |

## RQ-VAE

| 参数           |               当前基线 | 影响                  |
| -------------- | ---------------------: | --------------------- |
| input dim      |                   1024 | 输入表征契约          |
| latent dim     |                    128 | 量化空间容量          |
| codebook sizes |            256/256/256 | 3 层 SID 容量         |
| batch size     |                   1024 | code usage 统计稳定性 |
| learning rate  |              $10^{-3}$ | 收敛                  |
| weight decay   |              $10^{-4}$ | 正则                  |
| loss           |     MSE + quantization | 重建与离散化平衡      |
| K-means init   | 默认关闭，迭代上限 100 | codebook 初始化       |
| EMA codebook   |               默认关闭 | code 更新方式         |
| Sinkhorn eps   |                  0/0/0 | 均衡分配开关/强度     |

关键不是死记值，而是保证 codebook/version 与在线 SID 解析同步。

## 序列模型与在线 schema

需要版本化但不宜单独调的参数：

- USER/CONTEXT slot 顺序；
- 主/辅助序列最大长度；
- 时间 cutoff；
- token 层数与位宽；
- model `data_name`；
- padding、BOS/EOS 与 mask；
- Encoder 输出维度；
- Decoder 支持的 graph bucket。

这些属于接口契约。改变它们相当于改协议，必须端到端发布。

## 参数来源优先级

建议统一规则：

```text
request/experiment override
  > strategy/quota plan
  > model metadata
  > service config
  > code fallback
```

每个在线请求应打印或上报最终解析值，而不只记录原始实验参数。否则当多层默认覆盖时，排障人员无法知道实际生效的是哪一个。

## 调参四问

对每个参数都要能回答：

1. 谁写入，在哪个模块解析？
2. 缺失时回退到什么？
3. 硬边界由代码、模型还是硬件决定？
4. 改动会首先影响哪个指标？

例如 beam width：Entry 解析，缺失回退 180，当前 Decoder 上限 180，首先影响 Decoder latency/SID count，随后影响 KV、粗排、Ranking Fetch 覆盖和最终广告。

完整的作用链见 [[推荐系统理论/OneRec/召回粗排精排重排源码链路|召回、粗排、精排与重排源码链路]]。
