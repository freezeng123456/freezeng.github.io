参数必须按调用链分组。相同名字出现在样本、训练和在线服务中，不代表同一层含义。

## 在线生成式召回

| 参数               |             当前值/默认 | 硬约束                   | 主要影响              |
| ------------------ | ----------------------: | ------------------------ | --------------------- |
| `pam_beam_width`   |     新路径 fallback 180 | $\le180$                 | Decoder 前缀搜索宽度  |
| legacy beam width  |                     200 | 由旧模型/引擎约束        | 仅旧路径              |
| `beam_search_topk` |             $>0$ 时生效 | $\le$ 可输出候选         | 最终 SID 截断         |
| beam shard ratio   |              按策略配置 | 分片和需覆盖请求预算     | 分片负载与召回分布    |
| tree level         |         来自 trie/model | 必须与模型、SID 协议一致 | token 生成层数        |
| multi-level        |                    true | 需多级模型               | 是否逐层生成          |
| unique filter      |                  按策略 | SID 格式一致             | 去除重复 SID          |
| KV/output quota    | 策略给出；缺失兜底 1000 | 非负、有上限             | SID 扩展后的 TID 截断 |

详细 beam 语义见 [[推荐系统理论/OneRec/Beam-Search\|Beam Search]]。

## 在线 RPC 与超时

| 参数                  |       当前默认/评审值 | 说明                              |
| --------------------- | --------------------: | --------------------------------- |
| Datahub timeout       |               2000 ms | 获取序列与生成式上下文            |
| infer timeout         |               3000 ms | Encoder/Decoder/KV 整体或分段上限 |
| Ranking Fetch timeout | 需不小于 pipeline P99 | 等待 Retrieval Cache `fill_done`  |

评审记录中曾出现 Ranking Fetch 仅 140 ms，而联调流水线约 400–500 ms 的错配。这个数字只能视作待修配置快照，发布前必须用当前 P99 重新定标。超时不能简单加大：它受主链路总预算约束，应优先降低流水线时延并允许侧路失败快速降级。

## 样本与策略优化

| 参数                |   示例值 | 作用               | 调优风险                        |
| ------------------- | -------: | ------------------ | ------------------------------- |
| `return_ad_count`   |       40 | 生成器返回广告上限 | 过小截断，过大增加样本/排序成本 |
| `grpo_m_items_kept` |       20 | 组内保留候选数     | 必须不大于有效候选              |
| `creative_top_k`    |     1024 | 上游候选池         | 过大带入长尾噪声                |
| `creative_sample_n` |       20 | 创意采样数         | 影响多样性与方差                |
| `sampling_percent`  |      100 | 总样本采样率       | 改变数据量和分布                |
| `llm_sampling_rate` |     0.05 | 昂贵语义奖励覆盖率 | 成本/方差权衡                   |
| `gen_type`          | `MID_TD` | 输出格式           | trainer 必须同 schema           |

## RQ-VAE

| 参数           |               当前基线 | 影响                  |
| -------------- | ---------------------: | --------------------- |
| input dim      |                   1024 | 输入表征契约          |
| latent dim     |                    128 | 量化空间容量          |
| codebook sizes |            256/256/256 | 3 层 SID 容量         |
| batch size     |                   1024 | code usage 统计稳定性 |
| learning rate  |              $10^{-3}$ | 收敛                  |
| weight decay   |              $10^{-4}$ | 正则                  |
| loss           |     MSE + quantization | 重建与离散化平衡      |
| K-means init   | 默认关闭，迭代上限 100 | codebook 初始化       |
| EMA codebook   |               默认关闭 | code 更新方式         |
| Sinkhorn eps   |                  0/0/0 | 均衡分配开关/强度     |

关键不是死记值，而是保证 codebook/version 与在线 SID 解析同步。

## 序列模型与在线 schema

需要版本化但不宜单独调的参数：

- USER/CONTEXT slot 顺序；
- 主/辅助序列最大长度；
- 时间 cutoff；
- token 层数与位宽；
- model `data_name`；
- padding、BOS/EOS 与 mask；
- Encoder 输出维度；
- Decoder 支持的 graph bucket。

这些属于接口契约。改变它们相当于改协议，必须端到端发布。

## 参数来源优先级

建议统一规则：

```text
request/experiment override
  > strategy/quota plan
  > model metadata
  > service config
  > code fallback
```

每个在线请求应打印或上报最终解析值，而不只记录原始实验参数。否则当多层默认覆盖时，排障人员无法知道实际生效的是哪一个。

## 调参四问

对每个参数都要能回答：

1. 谁写入，在哪个模块解析？
2. 缺失时回退到什么？
3. 硬边界由代码、模型还是硬件决定？
4. 改动会首先影响哪个指标？

例如 beam width：Entry 解析，缺失回退 180，模型上限 180，首先影响 Decoder latency/SID count，随后才影响 KV、粗排和最终广告。
