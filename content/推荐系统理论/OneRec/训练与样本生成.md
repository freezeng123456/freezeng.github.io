## Sample Service 主流程

样本服务可从消息队列或本地输入读取曝光/反馈数据，核心生成器依次执行：

```text
RebuildMixerRequest
  → Mixer simulation
  → ParseFeatures
  → PrepareSequence
  → PickItems
  → GenerateFeatures/Rewards
  → SequenceExample or MID_TD
  → downstream storage
```

Mixer simulation 的目的不是完全复刻线上时延，而是恢复候选、位置和实验上下文，使训练样本与线上决策空间一致。

## 候选选择

当前 OneRec 生成器先取前 $M$ 个 item，并要求候选数至少为 $M$。重要参数：

| 参数                | 当前配置示例 | 含义                        |
| ------------------- | -----------: | --------------------------- |
| `return_ad_count`   |           40 | 生成器考虑/输出的广告数上限 |
| `grpo_m_items_kept` |           20 | GRPO 保留的 item 数 $M$     |
| `creative_top_k`    |         1024 | 进入创意候选池的 top-k      |
| `creative_sample_n` |           20 | 从候选池采样数量            |
| `sampling_percent`  |          100 | 样本流量采样比例            |
| `gen_type`          |     `MID_TD` | 下游训练数据格式            |

这些量存在层级关系：`creative_top_k` 是上游候选池，`creative_sample_n` 是采样数，`return_ad_count` 是广告输出边界，`M` 是优化/组内比较实际保留数。任何上游量小于下游需求都会造成隐式截断。

## 奖励与训练特征

生成器会写入多类信号：

- 价值：basic/quality/raised eCPM、eco value；
- 排序：rank score、rec score；
- 预估：pCTR、CVR 相关项；
- 体验：相关性、负反馈、重复、观看时长；
- 语义：LLM relevance、长期兴趣相关性；
- 业务约束与人群过滤。

原则是把“模型生成概率”与“业务价值/约束”分离：生成模型学习序列/语义分布，策略优化再利用多维奖励。不同奖励尺度必须标准化或显式加权，否则大数值字段会主导组内优势。

## 外部奖励 RPC

LLM 评估与其他奖励服务可并发调用以缩短样本生成时延，但多个回调不能同时写同一个 protobuf feature map；当前实现将 RPC 并发与最终 feature 写入串行化，避免 map 数据竞争。

示例配置中 LLM 评价开启，但只对约 5% 样本执行。`llm_sampling_rate=0.05` 控制的是昂贵奖励标注覆盖率，不是训练数据总采样率。

## GRPO/MCTS 类参数

配置支持：

- top-k sampling；
- 概率阈值与 min-p；
- MCTS 候选/分支控制；
- 二次采样；
- 强制保留曝光；
- 组内保留 $M$ 项。

这些开关必须与数据格式一起版本化。若 `M`、候选数或 reward 字段变化而 trainer 仍按旧 shape 读取，最好的情况是报错，最坏的情况是静默错位。

## 序列生成模型

训练数据把 USER、CONTEXT 与行为/广告序列送入序列模型，模型按层预测 SID token：

$$
p(c_1,\ldots,c_L\mid x)
=\prod_{l=1}^{L}p(c_l\mid x,c_{<l}).
$$

在线 Encoder 计算共享用户表示，Decoder 逐层扩展 token。因此训练必须覆盖在线使用的：

- token 层数与 masking；
- prefix 条件；
- padding/截断；
- 特殊 BOS/EOS 或业务 token；
- model `data_name`；
- 序列 schema 版本。

## 数据质量检查

| 检查                        | 失败含义                        |
| --------------------------- | ------------------------------- |
| 每个 slot 的缺失率/长度分布 | 特征路由或 USD 补全漂移         |
| SID 每层频率与 code usage   | RQ-VAE 死码或数据分布变化       |
| 完整 SID collision          | 量化粒度不足                    |
| reward 分位数与相关性       | 奖励服务/单位漂移               |
| 候选数漏斗                  | `top_k`、采样、过滤、$M$ 不一致 |
| 在线/离线 reader checksum   | schema 或模型版本错配           |

## 训练发布门槛

模型离线指标通过后，还应进行：

1. 固定样本 Encoder/Decoder golden test；
2. beam search 可重复性与最大宽度压力测试；
3. SID→TID 覆盖率回放；
4. 旧/新模型同请求 shadow 对比；
5. 小流量线上灰度，观察召回量、空结果、延迟和业务护栏。
