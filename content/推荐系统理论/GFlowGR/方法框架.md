## 1. 生成式推荐的基本对象

标准 GR 框架包含三块：

1. **Item tokenizer**：把商品映射成离散标识 token 序列 $\{t_l\}_{l\le L}$；
2. **User prompt**：拼任务描述、历史交互和画像；
3. **生成式 LLM**：自回归产出下一 item 的标识 token。

SFT 阶段常用 next-token prediction：

$$
\mathcal{L}_{\mathrm{GR}}(U,v)=-\sum_{l=1}^{L}\log P_{\mathrm{GR}}(t_l\mid U,\{t_i\}_{i<l}).
$$

论文示例里 $L=3$。这个目标只盯着单个正样本，既不区分交互价值，也不直接优化“一组候选”的质量。

## 2. 为什么换成 GFlowNet

把标识生成写成状态轨迹

$$
\tau=(s_0\to s_1\to\cdots\to s_L),\qquad s_0=\emptyset,\quad s_l=\{t_i\}_{i\le l}.
$$

![Item identifier 生成对应 GFlowNet 轨迹](assets/diagrams/gflowgr/zh/trajectory-flow.svg)

GFlowNet 要求任意完整轨迹的生成概率与终点奖励成正比：$P(\tau)\propto R(s_L)$。落到 GR 上有两个关键简化：

- 前向转移就是 LLM 的 token 概率：$P_F(s_{l+1}\mid s_l)=P_{\mathrm{GR}}(t_{l+1}\mid U,s_l)$；
- 反向转移确定：$P_B(s_l\mid s_{l+1})=1$，因为前缀拼接是唯一的。

因此，真正要设计的是 **轨迹从哪来** 和 **奖励怎么算**。

## 3. 三组件总览

![GFlowGR 训练时的三组件](assets/diagrams/gflowgr/zh/framework.svg)

对训练样本 $(U,v)$：

1. 轨迹采样器把正样本扩展成集合 $\{\tau_n\}_{n\le N}$；
2. 奖励模型给每条轨迹终点打分 $R(s_L)$；
3. 用 DB 或 TB 损失提供 token 级监督，并与 SFT 损失相加。

GFlowGR **只改微调目标**，推理仍按原 GR 解码；协同模型（CM）是可选插件，可同时服务采样和奖励。

## 4. 轨迹采样器

采样器目标是构造 set-wise 学习所需的 $N$ 条轨迹，其中 $\tau_1$ 对应正样本 $v$，其余为增强样本。

| 策略 | 做法 | 适用场景 | 风险 |
| ---- | ---- | -------- | ---- |
| 交互日志 | 取同一会话中另外 $N-1$ 个曝光/交互 item | 工业日志充足 | 曝光偏置会被直接带入训练 |
| 随机负采样 | 从全库均匀抽 $N-1$ 个未交互 item | 学术数据起步 | 后期负样本过易，梯度变弱 |
| CM 课程采样 | 先抽低分易负样本，再逐步提高难度 | 有可靠协同模型 | CM 噪声会污染课程顺序 |
| LLM on-policy | 用当前 LLM beam search 取 top-$(N-1)$ | 想贴近模型错误模式 | 成本高，早期分布不稳定 |

论文默认公开实验使用 **CM-based curriculum sampling**：早期优先低协同分的易负样本，后期加入更接近用户偏好的难负样本。

实现时建议固定一个候选池大小（例如 $2N-1$），再按课程规则从中取 $N-1$ 个增强轨迹，避免每步全库打分。

## 5. 行为感知奖励

![三类奖励信号的融合](assets/diagrams/gflowgr/zh/reward-model.svg)

对正样本轨迹 $\tau$ 与增强轨迹 $\tau'$，论文给出三类可组合信号：

1. **交互信号 $r_a$**：按行为层级赋值。文中示例为 liked $=10$，clicked $=1$，augmented / unpresented $=0$。
2. **估计分数 $r_{\hat{y}}$**：协同模型分数 $\mathrm{CM}(U,\cdot)$，或 LLM 自身的归一化生成概率。
3. **格式相似 $r_{\mathrm{sim}}$**：与正样本共享 token 数，衡量部分正确性：

$$
r'_{\mathrm{sim}}=\sum_{l=1}^{L}\mathbb{I}(t_l=t'_l),\qquad r_{\mathrm{sim}}=L.
$$

默认融合：

$$
R(s_L)=r_a+r_{\hat{y}}+r_{\mathrm{sim}}.
$$

也可换成可学习 Weighted Sum 或更深的 MLP。消融显示：Weighted Sum 在 top-5 更强，复杂 Deep Integration 反而无增益；去掉任一信号都会掉点，其中交互信号影响最大。

给未观测样本赋零交互奖励并不等于忽略它们：协同分和 token 相似仍能表达潜在相关性，这是缓解 exposure bias 的关键设计。

## 6. GFlowNet 训练目标

把 $P_F=P_{\mathrm{GR}}$、$P_B=1$ 代入后，得到 GR 场景下的详细平衡（DB）与轨迹平衡（TB）：

$$
\mathcal{L}_{\mathrm{DB}}(\tau)=\sum_{l=0}^{L-1}\left(\log\frac{F(s_l)\,P_{\mathrm{GR}}(t_{l+1}\mid U,s_l)}{F(s_{l+1})}\right)^2,
$$

$$
\mathcal{L}_{\mathrm{TB}}(\tau)=\left(\log\frac{Z\prod_{l=0}^{L-1}P_{\mathrm{GR}}(t_{l+1}\mid U,s_l)}{R(s_L)}\right)^2.
$$

其中 $F$ 是可学习 flow 估计器，在 DB 中终点满足 $F(s_L)=R(s_L)$；$Z$ 近似 $F(s_0)$。完整损失为

$$
\mathcal{L}(U,v,\{\tau_n\}_{n\le N})=\mathcal{L}_{\mathrm{GR}}(U,v)+\lambda\sum_{n=1}^{N}\mathcal{L}_{\mathrm{GFN}}(\tau_n).
$$

两个实现要点：

- **保留 $\mathcal{L}_{\mathrm{GR}}$**：防止只追 flow matching 而丢掉基础推荐能力；$\lambda$ 过大时论文明确观察到性能回退。
- **TB 通常强于 DB**：中间状态不唯一对应商品，整条轨迹与 item 的一一对应更适合 TB。

## 7. 训练与推理流程

按论文 Algorithm 1 的公开描述，训练循环可概括为：

```text
tokenize items → build prompt U
→ sample N trajectories (positive + augmented)
→ compute P_GR, flow F, reward R
→ optimize L_GR + λ Σ L_GFN
```

推理阶段只做：

```text
build prompt → generate identifier tokens → decode item
```

也就是说，GFlowGR 是 **训练期插件**，不是新的在线解码器。这使它更容易接到 TIGER、LETTER 或其他已有 GR backbone。
