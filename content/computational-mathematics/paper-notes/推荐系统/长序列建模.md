## 先看结论

长序列推荐要解决的核心问题很具体：用户历史已经增长到数千乃至数万条，在线模型仍要在严格的延迟和显存预算内，找出与当前候选相关的长期兴趣。完整保留全部行为能够减少信息损失，却会同步放大注意力计算、特征读取、缓存和系统稳定性压力。

目前的工业方案可按五条主线理解：

1. **检索**先从长历史中选出与目标最相关的少量行为，再做精细交互；
2. **压缩**把长历史编码为固定数量的兴趣表示，让线上成本与原始序列长度解耦；
3. **层次化建模**先处理局部片段，再通过全局表示传递长程信息；
4. **稀疏交互**只保留高价值的注意力边，直接控制交互图的规模；
5. **线性序列模型**用状态空间或混合器替代全量二次注意力。

这些路线之间没有固定胜负。检索强调目标相关性，压缩擅长沉淀稳定的长期兴趣，稀疏交互保留更多原始细节，层次化模型利用时间局部性，线性模型则提供更温和的复杂度增长。现阶段更稳妥的组合是：**用压缩表示维护长期记忆，同时用目标感知的语义稀疏交互保留候选相关细节**。

## 1. 问题怎样形成

设用户行为序列为

$$
H=(h_1,h_2,\ldots,h_L),
$$

当前候选的表示为 $q$。标准自注意力需要构造 $L\times L$ 的交互矩阵，时间和中间激活的规模近似为 $O(L^2)$。若候选还要与全部历史交互，额外成本通常至少随 $L$ 线性增长。线上系统面对的约束远多于一个复杂度符号：

- **特征 I/O**：数千条行为对应的 ID、上下文和多模态特征需要被读取、拼接与传输；
- **显存和缓存**：激活、KV cache、候选批量和模型参数共同占用设备内存；
- **尾延迟**：历史长度分布通常有长尾，超长样本会拉高 P95/P99 延迟；
- **训练稳定性**：更长的依赖路径、稀疏拓扑和负样本结构会改变优化难度；
- **线上一致性**：离线构造的索引、兴趣向量或语义邻接需要与在线特征保持一致和及时更新。

因此，长序列方案需要同时回答三个问题：

1. **保留什么信息？** 时间顺序、语义相似、兴趣迁移和低频长期偏好各自需要多少精度；
2. **何时引入目标？** 目标候选在检索、压缩、稀疏图构造或最终排序中的哪个阶段参与；
3. **成本放在哪里？** 计算可以进入离线索引、训练预处理、在线 GPU kernel 或轻量服务，但无法凭空消失。

## 2. 技术路线总览

| 路线       | 核心操作                               | 线上复杂度直觉                  | 主要优势                             | 主要风险                                 |
| ---------- | -------------------------------------- | ------------------------------- | ------------------------------------ | ---------------------------------------- |
| 检索       | 从 $L$ 条历史中选出 $K_r$ 条，再精排   | 与 $K_r$ 相关，另含检索成本     | 目标感知强，成本易控制，工程经验成熟 | 预筛选可能丢失迁移轨迹；粗细阶段可能失配 |
| 压缩       | 把 $L$ 条历史压成 $M$ 个兴趣 token     | 压缩完成后与 $M$ 相关           | 表示可复用，线上成本可与 $L$ 解耦    | 压缩有损，候选相关的局部细节可能被平均   |
| 层次化     | 局部块内交互，再汇聚到全局层           | 由块长、块数和全局 token 数决定 | 保留时间结构，适合局部连续兴趣       | 跨时间的语义跳转可能落在不同块中         |
| 稀疏交互   | 只计算窗口、语义近邻或指定方向的边     | 常见目标为 $O(LK_s)$            | 保留更多原始行为，模型上限较高       | 稀疏规则、索引和 kernel 都需要协同设计   |
| 线性模型   | 用递归状态或 token/channel mixing 聚合 | 通常随 $L$ 线性增长             | 长度扩展友好，显存压力较低           | 目标感知能力与大规模线上收益仍需验证     |
| 稠密端到端 | 保留完整序列和全量交互                 | 近似 $O(L^2)$                   | 信息路径最完整，训练目标直接         | 计算、显存和部署成本最高                 |

从演进过程看，早期方案重点解决“如何从很长的历史中找到候选相关行为”；随后，固定槽位兴趣压缩和层次化结构开始降低表示成本；近期工作把语义邻接、方向性注意力和系统级 kernel 优化合在一起，让模型在更长序列上保留更多细节。

## 3. 检索：先筛选，再精细交互

检索路线把长序列建模拆为两个阶段。粗阶段根据候选 $q$ 对历史行为打分，选出

$$
S(q,H)=\operatorname{TopK}_{i\in[1,L]} s(q,h_i),
$$

随后让精细模型只处理 $S$ 中的 $K_r$ 条行为。这里的关键不只是检索速度，还包括粗筛分数和最终排序目标的一致性。

### 3.1 SIM：两阶段范式

[SIM](https://arxiv.org/abs/2006.05639) 将系统分为 General Search Unit（GSU）和 Exact Search Unit（ESU）。GSU 用硬检索或软检索从长历史中得到较短的 Search-based Interest Sequence，ESU 再进行目标相关的注意力聚合。它建立了一个影响深远的工程范式：大部分历史在低成本阶段被过滤，昂贵交互集中在小集合上。

边界也很清楚。硬规则便于索引，却容易漏掉语义相关但类别不同的行为；软检索更灵活，但粗阶段的表示和监督若与最终任务分离，仍会形成阶段失配。

### 3.2 ETA：把哈希检索纳入任务训练

[ETA](https://arxiv.org/abs/2108.04468) 用 SimHash/LSH 将目标和行为映射为二进制码，以汉明距离完成快速筛选，并把这一过程与最终任务一起训练。它缓解了手工检索规则与排序目标之间的偏差，也让高维相似度搜索具备更低的在线开销。

需要关注的参数包括哈希位数、哈希表数量、候选桶大小和最终 $K_r$。位数过短会提高碰撞率，位数过长又可能降低召回；这些参数应联合观察召回率、目标指标和尾延迟。

### 3.3 TWIN：保持粗细阶段的一致性

[TWIN](https://arxiv.org/abs/2302.02352) 让 GSU 与 ESU 共享目标感知的相关性结构，并通过特征拆分和静态投影缓存降低粗阶段成本。稳定特征可以离线投影，在线只计算候选相关的轻量交互偏置。这样既保留目标感知能力，也减少两阶段使用不同打分空间造成的损失。

### 3.4 MUSE：用多模态语义改善检索

[MUSE](https://arxiv.org/abs/2512.07216) 把多模态 item 表示带入长序列检索，通过语义与行为对比学习构造更适合检索的嵌入，并在粗筛与精细建模中继续使用目标感知机制。它代表了一条重要趋势：当视觉、文本和行为语义被统一到可检索空间后，历史筛选可以跨越离散 ID 和类目边界。

这类方案依赖稳定的多模态表示服务、版本管理和索引刷新链路。语义模型更新后，历史 embedding 与在线候选 embedding 的版本差异也需要被监控。

### 3.5 适用边界

检索适合目标相关性很强、候选价值差异大、在线预算明确的场景，例如广告和强关联推荐。上线前至少需要验证：

- Top-$K_r$ 历史对最终目标的召回率；
- 粗阶段与精细阶段分数的相关性；
- 索引版本、增量更新延迟和回退策略；
- 检索耗时是否真正抵消了缩短序列带来的收益；
- 被筛掉的行为是否包含兴趣转移所需的过渡信息。

## 4. 压缩：把历史变成少量兴趣 token

压缩路线使用 $M$ 个学习到的查询或兴趣锚点，把长度 $L$ 的序列编码为

$$
Z=\operatorname{CrossAttention}(Q,H),\qquad Q\in\mathbb{R}^{M\times d},
$$

其中 $M\ll L$。最终模型只与 $Z$ 交互。只要兴趣表示能够预先生成或低频更新，在线复杂度便主要由 $M$ 决定。

### 4.1 BLIP-2 的结构启发

[BLIP-2](https://arxiv.org/abs/2301.12597) 属于视觉语言模型，这里借用的是它的结构思路。论文报告的 Q-Former 配置使用 32 个可学习 query token，通过 cross-attention 从冻结的图像编码器特征中抽取固定长度表示。对推荐系统的启发在于：一组小规模、可学习的查询可以成为长输入与下游模型之间的表示瓶颈。

这里不能直接推导出“32 个兴趣适合推荐”。推荐中的 $M$ 应由用户兴趣多样性、历史长度、目标指标和线上成本共同决定。

### 4.2 CFormer：压缩后回到原始行为表示

[CFormer](https://dl.acm.org/doi/10.1145/3746252.3761294) 先用学习到的 query 和 Transformer 编码历史，得到少量兴趣中心；训练中的解码或重建目标用于约束压缩质量。随后，它根据编码器末层注意力把每条历史行为硬分配给一个中心，并对原始行为 embedding 做池化。最终送入排序模型的兴趣表示因此仍保留原始特征空间的信息。

这套设计包含四个环节：

1. 学习 query，形成兴趣 token；
2. 用重建目标避免压缩表示坍缩；
3. 根据注意力完成行为到兴趣中心的硬分配；
4. 在每个分组内池化原始行为表示，并与候选交互。

实现时需要明确兴趣数 $M$、分配温度或硬化策略、重建损失权重、空簇处理和兴趣更新频率。若兴趣离线生成，还要测量陈旧兴趣对短期偏好的影响。

### 4.3 UxSID：兴趣锚点与语义 ID 协同

[UxSID](https://arxiv.org/abs/2605.09040) 使用 Interest-Aware Information Compression 将长历史压缩到 $M$ 个兴趣锚点，再利用候选的语义 ID（SID）进行分层探测：

- **全局探测**让目标 SID 查询原始行为，捕获广泛相关性；
- **局部探测**先由全局兴趣调节 SID，再查询压缩后的兴趣锚点；
- **融合层**合并全局与局部结果，形成目标相关的用户表示。

这种结构把可复用的长期兴趣和候选语义放入同一条路径。代价是系统需要稳定的 SID 生成、存储、版本同步和在线查询能力。

### 4.4 压缩的合理定位

固定长度兴趣适合电商、工具型产品以及兴趣相对稳定的内容场景。它也适合作为长序列系统的基础记忆层。压缩后的表示对多个候选可复用，能够显著降低逐候选交互成本；同时，有损瓶颈会削弱稀有行为和短期突变。较稳妥的设计是保留一条面向当前候选的精细路径，用它补足压缩记忆中的局部信息。

## 5. 层次化：让局部片段和全局状态分工

层次化方案把历史划分为若干 chunk。每个 chunk 先完成局部建模，再把摘要 token 送入全局层：

$$
z_j=f_{\text{local}}(h_{(j-1)B+1:jB}),\qquad
u=f_{\text{global}}(z_1,\ldots,z_{\lceil L/B\rceil}).
$$

这里的 $B$ 是块长。局部层保留相邻行为的细节，全局层负责跨块传播。HAT 一类结构可以按这个抽象理解。它对连续观看、会话和周期性行为较自然，因为相近时间内的交互往往共享上下文。

风险来自分块假设。语义相近的行为可能相隔很远；如果每个块只留下一个摘要，跨时间的兴趣回访会被压缩两次。块边界、重叠宽度、全局 token 数和位置编码都需要单独做敏感性分析。

[LONGER](https://arxiv.org/abs/2505.04421) 将全局 token、token merge、轻量 InnerTransformer 与混合注意力结合，并同时考虑混合精度、激活重计算、KV cache 和训练服务系统。它说明层次化方法的实际能力取决于算法与运行时的共同设计。层次化结构在混合方案中还可承担时间维度的局部压缩，让语义稀疏层集中处理跨块关联。

## 6. 稀疏交互：直接设计高价值的注意力边

稀疏路线保留原始行为节点，只让注意力矩阵中的一部分位置参与计算：

$$
A_{ij}=
\begin{cases}
\operatorname{softmax}(q_i^\top k_j), & (i,j)\in\mathcal E,\\
0, & \text{其他位置},
\end{cases}
$$

其中 $\mathcal E$ 可以由方向、时间窗口、语义近邻或业务结构定义。若每个节点只连接 $K_s$ 个邻居，主计算量可从 $O(L^2)$ 降到 $O(LK_s)$。

![语义稀疏交互与压缩记忆的混合架构](assets/diagrams/long-sequence-recommendation/zh/hybrid-memory.svg)

### 6.1 由结构先验定义稀疏边

[微信视频号公开技术文章](https://mp.weixin.qq.com/s/xPidLQfNEF-fCCVksT9u_w) 展示了一类面向长序列推荐的结构化设计：候选对历史执行单向 cross-attention；序列内部再根据感知相似性、感知相关性和感知邻域建立有限交互。

- **感知相似性**把高维行为表示转成与候选的相似度和属性信号；
- **感知相关性**先将历史聚成 $K$ 个兴趣，再用候选读取聚合结果；
- **感知邻域**使用滑动窗口保留局部上下文，并据此修正目标注意力；
- **多域交互**通过二维或 cross-mask 结构限制字段和行为之间的连接方向。

这类规则能把业务认知直接放入交互图，解释性也较强。随着特征域和任务增加，掩码会快速复杂化，因此要为每类边记录独立的覆盖率、耗时和增益。

### 6.2 EST：用多模态语义建立 Top-$K$ 邻接

[EST](https://arxiv.org/abs/2602.10811) 包含两项关键设计：

1. **LCA（Lightweight Cross-Attention）**保留 Non-behavior 到 Behavior 的高价值交互方向，删除收益较低的其他方向；
2. **CSA（Content-aware Sparse Attention）**使用冻结的多模态 embedding，为每个行为构造语义 Top-$K$ 邻居。

论文设置中的语义邻居数为 $K=5$，于是序列内部注意力从全连接图变成每行只有少量边的邻接图。这个数值是论文配置，不应直接作为所有线上场景的默认值。工程上应同时扫描 $K_s$、语义模型版本、邻接更新频率和无邻居回退策略。

### 6.3 ULTRA-HSTU：半局部注意力与系统优化

[ULTRA-HSTU](https://arxiv.org/abs/2602.16986) 采用半局部注意力：非行为 token 可以完整读取行为序列，行为 token 之间主要通过局部窗口连接。论文还把低精度计算、专用 kernel、输入组织和分布式执行纳入整体优化。

这个方向的重要经验是，稀疏矩阵只有在运行时真正跳过无效边时才会产生端到端收益。若框架先生成稠密矩阵再乘 mask，理论复杂度下降不会自动转化为延迟下降。实现中需要检查：

- 稀疏拓扑能否被 block 化或编译为规则 kernel；
- 邻接索引的读取是否成为新的带宽瓶颈；
- FP8/BF16 下的数值稳定性与校准策略；
- 训练和推理是否使用相同的稀疏语义；
- 动态序列长度下的负载均衡和批处理效率。

## 7. 线性序列模型：把历史折叠进递归状态

### 7.1 Mamba4Rec

[Mamba4Rec](https://arxiv.org/abs/2403.03900) 把 selective state-space model 引入序列推荐。连续形式可写为

$$
h'(t)=A(t)h(t)+B(t)x(t),\qquad
y(t)=C(t)h(t)+D(t)x(t).
$$

离散实现沿序列更新有限维状态，复杂度近似随 $L$ 线性增长。Selective 机制让步长和部分状态参数依赖输入，使模型能够按内容选择保留或遗忘信息。

它适合显存紧张、序列很长且需要顺序扫描的场景。推荐排序仍经常需要候选与历史之间的显式目标感知交互，因此可在状态空间主干之外增加轻量 target-aware 层。性能评估还应确认框架是否提供高效的 selective-scan kernel；朴素循环会削弱理论优势。

### 7.2 TokenMixer-Large

[TokenMixer-Large](https://arxiv.org/abs/2602.06563) 在固定长度的异构特征 token 上交替执行 token mixing 与 channel mixing，并结合 mixing-and-reverting、残差连接和稀疏 Mixture-of-Experts。它更接近高效特征交叉模型，不能等同于对任意长度行为序列的完整替代。

它的工程问题集中在 MoE 路由、专家负载均衡、低精度训练和 token 并行。若用于长序列系统，更合适的位置可能是压缩或检索之后的特征交互层。

## 8. 如何做技术选型

![长序列推荐的技术选型框架](assets/diagrams/long-sequence-recommendation/zh/decision-framework.svg)

### 8.1 从业务信号出发

| 场景特征                                         | 优先路线            | 原因                                               |
| ------------------------------------------------ | ------------------- | -------------------------------------------------- |
| 广告、强相关候选、实时目标明显                   | 检索                | 先找与候选直接相关的历史，精度优先且在线预算可控   |
| 短视频或内容流、历史极长、兴趣漂移快、多模态丰富 | 语义稀疏交互 + 压缩 | 稀疏路径保留候选相关细节，压缩路径提供稳定长期记忆 |
| 电商或工具型产品、类目较固定、长期偏好稳定       | 压缩                | 兴趣 token 可跨候选复用，成本容易与原始长度解耦    |
| 会话连续性强、局部时间结构明显                   | 层次化 + 局部窗口   | chunk 内保留连续模式，全局层传递慢变化状态         |
| 显存受限、离线研究或序列长度需要快速扩展         | 线性模型            | 复杂度和激活随长度增长较温和，便于建立长上下文基线 |

### 8.2 从团队资源出发

| 计算资源 | 工程能力 | 建议起点                                                   |
| -------- | -------- | ---------------------------------------------------------- |
| 有限     | 较强     | 两阶段检索；先从规则或哈希检索做起，再逐步增加语义表示     |
| 充足     | 较强     | 语义稀疏交互；同步设计索引、kernel、低精度和监控           |
| 有限     | 有限     | 固定槽位压缩；尽量与主排序模型解耦，先验证复用收益         |
| 充足     | 有限     | 先完成离线和小流量验证，暂缓复杂自定义 kernel 或全链路重构 |

### 8.3 一个可落地的混合架构

推荐的混合系统可以分成两条并行路径：

1. **长期记忆路径**：将全部历史压成 $M$ 个兴趣 token，按用户低频更新，并允许多个候选复用；
2. **候选精细路径**：用多模态语义和时间窗口，从原始历史中选择 $K_r$ 条行为或为每个节点建立 $K_s$ 条边；
3. **融合层**：让候选同时读取兴趣 token 与稀疏行为子图，再进入排序头。

这种分工让长期偏好和即时相关性拥有不同的容量与更新频率。若语义索引暂时不可用，系统仍可退化到兴趣记忆加近期窗口；若兴趣缓存过期，候选精细路径仍能读取最新行为。

## 9. 关键参数与实验设计

长序列方案的参数应按“信息容量、计算预算、数据新鲜度”三组管理：

| 参数                   | 含义                 | 主要影响                   | 建议观测                                     |
| ---------------------- | -------------------- | -------------------------- | -------------------------------------------- |
| $L_{\max}$             | 最大历史长度         | 信息覆盖、特征 I/O、尾延迟 | 指标随长度的收益曲线，P50/P95/P99 长度和延迟 |
| $K_r$                  | 检索保留的行为数     | 目标行为召回与精排成本     | Top-$K$ 召回率、最终指标、检索与交互耗时     |
| $M$                    | 压缩兴趣 token 数    | 兴趣容量与逐候选成本       | 重建质量、兴趣利用率、空槽率、指标饱和点     |
| $B$                    | 层次化块长           | 局部细节与全局 token 数    | 跨块关联损失、边界敏感性、块内耗时           |
| $W$                    | 局部注意力窗口       | 时间连续信息与稀疏度       | 不同时间跨度的贡献、窗口边界效应             |
| $K_s$                  | 每个节点的语义邻居数 | 语义覆盖与稀疏 kernel 成本 | 邻居召回、有效边比例、稀疏算子吞吐           |
| $d$                    | 序列表示维度         | 表达能力、显存和带宽       | 参数量、激活、吞吐及小维度退化               |
| $T_{\text{refresh}}$   | 索引或兴趣刷新周期   | 新鲜度、更新成本           | 陈旧率、版本差异、增量任务延迟               |
| $\lambda_{\text{aux}}$ | 重建或对比学习权重   | 表示结构与主任务平衡       | 主任务指标、辅助损失、梯度比例               |

建议按以下顺序做消融：

1. 固定模型容量，扫描 $L_{\max}$，确认更长历史确实增加有效信息；
2. 分别建立检索、压缩、局部窗口和线性模型基线；
3. 固定延迟或 FLOPs 预算比较各路线，避免只比较参数量；
4. 对语义稀疏模型扫描 $K_s$，并与随机邻居、时间邻居和类目邻居对照；
5. 对压缩模型扫描 $M$，检查兴趣槽是否被均匀使用；
6. 测试兴趣漂移、冷启动、历史缺失、语义索引过期和超长异常样本；
7. 报告训练吞吐、在线批量、平均延迟、尾延迟、显存峰值和特征服务开销。

> [!important] 理论稀疏度需要端到端测量
> FLOPs、注意力边数和模型参数只能解释一部分成本。线上收益还受到索引查询、特征拉取、数据搬运、kernel 启动、padding、批处理和回退流量影响。所有方案都应在相同硬件、相同批量和相同输入分布下报告完整延迟。

## 10. 工程评审清单

### 信息与目标

- 每类历史行为在进入模型前经历了哪些截断、过滤、聚类或池化？
- 目标候选在哪一层参与，训练和推理是否一致？
- 是否保留时间顺序、重复消费、负反馈和兴趣回访？
- 多模态 embedding 是否真的改善目标行为召回，还是只提升了离线相似度？

### 系统与成本

- 稀疏算子是否实际跳过无效边，还是仍构造稠密矩阵？
- 兴趣 token、哈希桶和语义邻接分别在哪里生成、存储与更新？
- 超长用户如何限流、分桶或异步处理？
- 线上失败时能否回退到近期窗口、短序列模型或缓存兴趣？

### 一致性与可观测性

- 语义模型、索引、兴趣缓存和排序模型是否带有可追踪的版本号？
- 是否监控邻居覆盖率、兴趣槽利用率、序列截断率和索引陈旧率？
- 离线训练样本能否复现线上截断、刷新周期和回退逻辑？
- 发布后是否按历史长度、活跃度、兴趣漂移和冷启动状态分桶观察指标？

## 11. 研究判断

长序列推荐正在从单一结构竞争转向算法与系统的联合设计。三点趋势值得持续跟踪：

1. **混合架构会更常见。** 压缩记忆承担稳定、可复用的长期状态；稀疏交互承担候选相关的精细读取。
2. **多模态语义会逐渐成为基础设施。** 它既可用于检索，也可用于构图、聚类、冷启动和语义 ID；收益上限取决于表示质量与版本一致性。
3. **生产上限取决于运行时。** 稀疏注意力、低精度、缓存、索引和动态批处理需要共同设计，单独降低公式复杂度通常不够。

现有公开结果支持这些方向的可行性，尚不足以证明某条路线在所有场景中胜出。真正可靠的选择仍应基于业务信号、等成本消融和端到端在线测量。
